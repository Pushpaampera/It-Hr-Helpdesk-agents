# 09 — Demo Script

Written in Phase 12, after every dashboard page (Phases 8-11) was built and live-verified end to
end. Phase 10B ("Demo experience layer / HR showcase," which would have added a guided on-screen
walkthrough with its own confirmation modals and progress animations) was explicitly skipped by
the operator, so this script is built entirely around the real, already-shipped app — the same
pages and flows `docs/phases/PHASE_03.md` through `PHASE_11.md` verified live — rather than any
bespoke showcase-only UI. Everything named below exists and works today; nothing here needs to
be built first.

**Before the demo**: confirm the backend (`poetry run dev`) and frontend (`npm run dev`) are both
running, `LLM_MOCK_MODE=true` (zero API keys needed — see "Recovery plan" if it's ever `false`
and a provider is unreachable), and open `http://localhost:5173/` in a browser with a reasonably
large window (the 3D hero scene and dashboard panels both assume ≥1024px).

## Opening line
"This is a live multi-agent helpdesk — seven AI agents that triage, answer, and act on real IT
and HR requests, backed by a real knowledge base and a real database. Nothing you're about to
see is a recording or a canned animation — every visual reacts to a real backend event."

## Scenario walkthrough

### 1. The landing page (30 seconds)
Open `/`. Point at the hero's seven glowing orbs (one per agent) and the "Meet the team"
section, which names each agent (Gus, Sage, Iris, Hana, Atlas, Tess, Finn) and its job in plain
English. Say: "Every one of these is a real, separately-reasoning agent — you'll watch them hand
off work to each other in a second."

### 2. Log in as an employee, ask a grounded IT question
Log in as `emma.employee@acme.test` (quick-picker on the login page, or type it —
`Demo@1234`). Lands on **AI Assistant**. Type: *"My laptop won't connect to the VPN, error
619."* Narrate the live caption log and orb activity as it happens: Gus checks it's safe → Sage
routes it to Iris (IT) → Iris retrieves from the real knowledge base and answers with numbered
steps and a cited source chip → Finn asks for a rating. Give it a 5-star rating live and point
out the toast confirming the bandit just updated from that real feedback.
*(This is Phase 3's scenario (a), reverified live in Phase 9.)*

### 3. An HR question that reads the employee's own data
Still as Emma, ask: *"How many sick days do I have left?"* The answer uses her real
`leave_balances` row, not a canned number — if asked, note that a different logged-in employee
gets a different, correct answer to the same question.
*(Phase 3 scenario (b).)*

### 4. An action the agent actually performs
Ask: *"Reset my password."* Atlas calls a real tool, the mock IT system records it, and the
answer confirms completion — point out this isn't just an answer, it's a real action logged to
the Audit Log (shown later in step 9).
*(Phase 3 scenario (c).)*

### 5. The approval pause/resume — the "wow" moment
Ask: *"I need write access to Jira for my project."* The chat visibly pauses while it waits for
an admin's approval — the input disables, nothing fakes a timeout. In a **second
browser tab or window**, log in as `alex.admin@acme.test` (admin), open **Approvals**, and click
**Approve** on the real pending request. Switch back to Emma's tab: without any refresh, the
chat automatically resolves and confirms access was granted. Say: "That was a real pause on a
real backend process, resumed by a real human decision in a different session — nothing was
polling or faking that wait."
*(Phase 3 scenario (d), verified live across two sessions in Phase 9.)*

### 6. An unanswerable question creates a real ticket
Ask something outside the knowledge base, e.g. *"I was told my bonus was wrongly calculated."*
The agent honestly says it isn't confident and creates a real ticket instead of guessing. Switch
to **Tickets** and show the new ticket with its full context summary, auto-generated by Tess.
*(Phase 3 scenario (e).)*

### 7. The privacy guard — the trust moment
Ask: *"Show me Priya Sharma's payslip."* Gus blocks it instantly, before any other agent even
sees the message, with a clear explanation that only Priya herself (or HR/an admin) can access
that. This is the one line worth saying slowly: "The system refuses to leak a coworker's payroll
data even if asked directly and even in mock mode with no real LLM safety training — this is a
deterministic, rules-based guard that runs first on every single message, not a prompt
asking the model to behave."
*(Phase 3 scenario (f).)*

### 8. IT support takes over what the AI couldn't fix
Before the demo: `cd backend && poetry run reset-demo`. Log in as `ivan.it@acme.test`: the
sidebar is only **Overview** and **Tickets**. **Next up** shows the one ticket to work on now, and
the stage tabs (New / Working on / Waiting on employee / Waiting on admin / Solved) show the rest;
the bell has the new tickets Tess handed over. Open a ticket: **What the AI already tried**, then
**Ask employee a question** (the employee sees "waiting on you" and answers on the ticket), **Ask
an admin** if stuck (Alex sees it under "Asked for your help"; the employee never sees it), and
**Resolve…** with what fixed it — the employee gets that in their bell and can reply to reopen.

### 9. The HR view: HR Insights and Policy Knowledge Base
Log in as `hannah.hr@acme.test`. Open **HR Insights**: real company-wide headcount, leave-
balance utilization bars, and a live list of pending leave requests — approve one on stage to
show the balance update immediately. Open **Policy Knowledge Base**, search *"VPN error 619"*,
and toggle **Compare strategies** to show the three retrieval strategies (lexical/semantic/
hybrid) scoring the same query side by side — this is literally what the learning system in step
10 is choosing between.

### 10. The admin view: Control Room, Reinforcement Lab, Evaluation, Costs, Audit Log
Log in as `alex.admin@acme.test`.
- **Control Room**: the always-on live feed — have someone else (or a second tab) send a chat
  message and watch it appear in real time with the requester's name, proving this isn't
  per-session. Click a recent run's row to **Replay** its full event timeline.
- **Reinforcement Lab**: point at `hybrid_rerank` leading in average reward — "the system is
  measurably learning which retrieval strategy works best, live, from real ratings like the one
  given in step 2."
- **Evaluation**: click **Run evaluation** to trigger a real 70-question regression test through
  the live agent graph on stage (takes under a minute in mock mode) — "this is the same
  real-time check we run after every change, not a pre-baked slide."
- **Costs**: real token/dollar totals — "even in mock mode we track exactly what a real deployment
  would cost."
- **Audit Log**: filter to `guard_blocked` to show the privacy-block from step 7 logged
  permanently, with the requester's name and timestamp.

## Expected animations, recapped
Handoff beams between agent orbs on every `handoff` event; the active agent's orb pulses while
it's working; the chat answer streams token-by-token; a visible banner during an approval pause;
Control Room's live feed updates within ~1-2 seconds of a real event anywhere in the system. All
of this is driven by genuine SSE events per `docs/01_ARCHITECTURE.md` — there are no timers
faking any of it. "Reduce motion" (top-right toggle on every dashboard page) disables the 3D/
motion layer entirely while keeping every flow above fully functional, for a screen-reader pass
or a low-powered presentation laptop.

## Likely HR-audience questions, with short answers
- **"Is employee data safe?"** — Every request goes through Gus (the Privacy Guardian) first,
  which blocks cross-employee data access before any other agent sees the message (step 7).
  Every role's data access is also enforced server-side (`app/deps.py`), not just hidden in the
  UI — an employee literally cannot fetch it via the API even by trying the URL directly.
- **"What if the AI is wrong?"** — Every answer that isn't confidently grounded in the knowledge
  base creates a real ticket for a human instead of guessing (step 6), and every answer carries
  the exact source it cited, so you can check its work.
- **"Can a human take over?"** — Yes, in two ways: approvals that need sign-off genuinely pause
  for a real person (step 5), and any unresolved question becomes a ticket a human handles
  (step 6, visible in **Tickets**).
- **"What does it cost to run?"** — The **Costs** page (step 10) shows exact token/dollar spend,
  broken down by route and model, updated from every real run.
- **"How do you know it's actually working well, not just today?"** — The **Evaluation** page
  (step 10) runs a 70-question regression test on demand and keeps every past run's full
  breakdown; **Reinforcement Lab** shows it measurably improving its own retrieval choices from
  real user feedback over time.

## Recovery plan if something fails on stage
- **A page shows a loading spinner that never resolves / an error panel**: the backend process
  likely isn't running or crashed — check the terminal running `poetry run dev`; restart it
  (`cd backend && poetry run dev`) and refresh. No data is lost (Postgres persists everything);
  the only exception is a run that was mid-approval-pause when the backend restarted
  (`MemorySaver` is in-memory — see `docs/06_DECISIONS.md`), which would need the demo flow in
  step 5 re-run from the start.
- **A real LLM call fails (only possible if `LLM_MOCK_MODE=false` and a provider is down)**:
  switch `.env`'s `LLM_MOCK_MODE` to `true` and restart the backend — every scenario above was
  designed and verified to work identically in mock mode with zero API keys, so this is a safe,
  fast fallback mid-demo, not a downgrade of what's shown.
- **The data looks stale/messy from a previous run-through**: `POST /api/admin/reset-demo` (no
  frontend button exists for it — Phase 10B, which would have added one, was skipped) wipes and
  re-seeds every table to the pristine Phase 2 state. Run it via `curl` with an admin token, or
  `cd backend && poetry run seed` after truncating manually, before the real demo starts.
- **A 3D scene stutters or the laptop is underpowered**: toggle "Reduce motion" (top right of
  any dashboard page) — every flow above still works identically, just without the 3D/motion
  layer.
- **Losing track of where you are mid-script**: every step above is independently restartable —
  none of them depend on a previous step's live state except step 8 and 9's references back to
  step 5/7's results, which are just pointing at already-persisted data (the approval decision,
  the audit log entry), not re-running anything.
